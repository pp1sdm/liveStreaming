# 韩语答题直播

抖音韩语学习答题直播的服务端。主持人念韩语提示，观众在评论区打 `a b c d` 作答，
倒计时结束公布答案、结算积分。

**整场不需要人盯着。** 到时间自动换题，全程有语音讲解和串场，AI 出题、AI 主持。

```text
  弹幕源 ──► 判定 ──► 会话状态 ──SSE──► /overlay   （OBS 浏览器源）
                          │
                          └───导演───► DeepSeek（出题/讲解/控场）
                                 └────► Edge 语音合成 ──► /voice/{id}
```

## 跑起来

```bash
cp .env.example .env      # 填 DEEPSEEK_API_KEY
cargo run -p livestream-app
```

| 地址 | 用途 |
|---|---|
| `http://127.0.0.1:7331/overlay` | OBS 浏览器源（源设成 1920×1080） |
| `http://127.0.0.1:7331/console` | 主播控制台（想插手时用，不插手它自己会走） |

画面页的开关（叠加在 URL 上）：

- `?solid=0` 去掉米黄底，叠在摄像头上用
- `?sfx=0` 关音效，`?voice=0` 关语音和字幕（两者独立）
- `?vol=0.72` 调音量

**声音要进直播**：OBS 里右键那个浏览器源 → 高级音频属性 → 音频输出改成「输出到 OBS」。
默认是「监听」，本地能听见但录不进去。

弹幕源：默认是自己造弹幕的演示源。接真实弹幕要先起本地转发工具，然后

```bash
DANMAKU_WS=ws://127.0.0.1:8888 cargo run -p livestream-app
```

## 密钥

`DEEPSEEK_API_KEY` 写在项目根目录的 `.env` 里（已在 `.gitignore` 中）。
不进代码、不进命令行参数（参数会出现在 `ps` 里）、不进日志。

**没有 key 也能跑完整场直播**——退化成题库循环加本地台词，答题流程一步不少。
开发时不必先搞到 key。

### 代理：默认直连

DeepSeek 的调用**默认不走代理**，`HTTP_PROXY` / `HTTPS_PROXY` 会被忽略。
这不是洁癖：`reqwest` 会自动读那两个变量，而它们常常是给浏览器或别的工具设的
（开发机上就有一个 Clash），于是每一次讲解调用都悄悄从那儿绕一圈——代码里看不见、
日志里没有、`curl` 直连又通，出了故障只能靠猜。要挂代理就设 `DEEPSEEK_PROXY`，
启动时会打日志说明走哪条路。

单个请求失败会**自动重试一次**（间隔 400 毫秒）。只重试「这一次不走运」的失败：
连不上、429、5xx、响应体坏了。401/403 这类原样重发也是同样的答复，超时则不该
接着等——一次 20 秒，重试就是 40 秒起步，这 40 秒里直播是停着的。两次都没成才记
一次熔断计数，所以偶发抖动不会把熔断器推开。

## 语音

**在服务端合成，页面只负责播。** 不是偷懒，是 OBS 的浏览器源用不了
`synthesisSpeech`：CEF 没实现 Web Speech 后端，`getVoices()` 永远是空的；就算响了，
OBS 也录不进去（勾了 "Control audio via OBS" 也不行，官方说 probably not fixable）。

用的是 Edge 的在线合成接口，免费，不用申请。台词按语言分段（`Segment::zh` /
`Segment::ko`）——中文音色读韩语会把「학교」按汉字音读成 xiào，一耳朵就听出来了。
合成结果拼成**一个** MP3 再推给页面：分开播的话每段之间会有一道几十毫秒的缝。

### 时钟偏移会让语音挂掉

`Sec-MS-GEC` 是一个按当前时间算的签名，有效窗口 5 分钟。**系统时钟偏移超过 5 分钟，
合成就会一直返回 403。** WSL2 在宿主机休眠之后很容易漂掉。

症状是「日志里全是 403、一点声音都没有」。修：

```bash
sudo hwclock -s
```

代码里遇到 403 会重算一次时间戳重试，仍失败就报一条能直接照着修的错，
而不是把 403 原样抛出来让人猜。

## 结构

| crate | 管什么 |
|---|---|
| `core` | 题目、选项、弹幕这些纯数据 |
| `engine` | 一道题的生死：报题 → 收答 → 封盘 → 公布，判定和计分 |
| `danmaku` | 弹幕来源（真实转发工具 / 演示源） |
| `ai` | DeepSeek 客户端、Edge 语音合成、提示词。**不认识「直播」** |
| `web` | HTTP、SSE 推送、画面状态 |
| `app` | 接线，以及[导演](crates/app/src/director.rs) |

## 两条容易踩的设计约束

**一、防跟风，公布前谁也看不见别人的答案。**

`OverlayState.tally` 是 `Option`，只有公布那一刻才是 `Some`——泄漏在类型上不可表达，
不是靠调用方自觉。出题时选项还要打乱：模型偏爱把正确答案放在 A，实测连出三道都是 A，
「答案永远是 A」本身就是一种跟风信号。见 `GeneratedQuestion::into_question`。

**二、AI 的弹幕互动不是「念弹幕」。**

是控场：把几十条弹幕压成一份摘要（多少人、多少条、几条在聊韩语、几条**消毒过的**样本），
让模型据此说一句稳住节奏的话。频率受限（约 25 秒一次，只在收答期）。

消毒是硬要求：[`sanitize_danmaku`](crates/ai/src/script.rs) 在**进门时**就丢掉含答案痕迹、
链接广告、纯选项字母的内容。DeepSeek 本身有判别力，但那是第二道防线——无人值守的直播里，
「它这次应该会拒绝」不是能接受的保证。

## 测试

```bash
cargo test --workspace
cargo clippy --workspace --all-targets
```

打真实接口的测试标了 `#[ignore]`，要手动跑：

```bash
cargo test -p livestream-ai -- --ignored --nocapture
cargo test -p livestream-app -- --ignored --nocapture refills_itself
```

会真的调 DeepSeek 出题、真的打微软的合成接口。**会花掉一点额度。**

第二条单独说一下：它验的是「题库见底 → 自动出题 → 补回题库」这条闭环。
演示题库有三十来道，`BANK_LOW_WATER` 是 2，**线上要跑三十多分钟才碰得到一次**——
光靠盯着直播间看是验不到的，而它偏偏是「AI 出题」这个卖点的全部实现。
测试里只放一道题，让它在第一秒就触发，走的是和线上同一份代码。
